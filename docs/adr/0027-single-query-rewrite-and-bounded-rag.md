# 单条查询改写和有界 RAG 编排

- Status: Accepted
- Date: 2026-08-21

## Context

此前 RAG 规划器固定生成 2-3 条查询，并对每条查询执行一次真实召回；证据复核不足时还会生成 follow-up 查询并再次召回。对于每个查询都需要 embedding 和混合检索，这会线性放大延迟、外部调用和失败面，同时当前知识库规模与已有 BM25、KNN、RRF、确定性重排能力并不要求默认展开多个查询。

## Decision

RAG 请求只执行一次 LLM 查询改写，输出一条检索 query；改写失败时使用用户原问题。随后只调用一次 `EvidenceRetriever`，保留一次证据复核，但复核只输出 `sufficient` 和 `reason`，不得生成或触发补充检索。

保留现有 `EvidenceRetriever` seam、Elasticsearch 混合召回、父章节回填、证据字符预算、确定性证据质量门槛和高风险安全回答路径。检索失败仍显式返回 `FAILED`，不静默切换检索后端。

## Consequences

- 正常请求的检索调用数固定为 1，RAG 编排成本和失败面可预测。
- 查询覆盖面可能低于多查询召回，必须通过完整 RAG 评测中的必要证据命中、证据复核、回答成功率和延迟指标持续观察。
- 如果后续评测证明长尾问题需要补召回，只能另行设计有明确条件和最大次数的 fallback，不恢复无条件多查询规划。
